VERDICT: The design's skeleton is genuinely shippable — gates G1–G3, the D1/D2 fallback ladder, cache-everything, and the pre-registered D6 stats are the right hackathon instincts, and nothing on the never-cut list is missing. But it carries roughly 6–9 hours of ballast for a solo builder with ~12.5 working hours left, and its single worst defect is that the documented dashboard fallback (static Plotly HTML) destroys the demo's best moment rather than saving it. Apply before writing code: (1) fix the dashboard degradation path to section-cutting, never stack-switching, and pre-rank the four must-have sections; (2) replace content-addressed caching with fixed paths + --force + a sidecar run.json; (3) diet the map schema to ~15 fields and let s6 remap add the rest on demand; (4) delete the s2 LLM filter pass (the map's eligible flag already does that job) and the C+B merged triage probe (count-only queries suffice); (5) cut bootstrap/permutation to 200/100 with per-resample try/except, incremental checkpoints, and a full dry-run at M4, and pre-commit grouped-CV ΔLL + permutation p as the one headline stat; (6) drop research_group and author_conclusion_agrees. With those cuts the clock-pinned milestones are achievable; without them, M2 slips at 5 PM, the overnight run is fragile at exactly the hours no one is watching, and Sunday morning becomes triage instead of assembly.

[blocker] (D9 dashboard + §6 cut order (static Plotly HTML fallback)) The dashboard plan is over-scoped (7 sections per context §23) AND its documented escape hatch is a trap: 'fall back to static Plotly HTML export' is NOT cheaper than minimal Streamlit for the one interaction the demo cannot lose — click a tree leaf, see evidence cards with source-line links. Static Plotly HTML cannot do cross-filtering into evidence cards without custom JS; Streamlit does it in ~10 lines (selectbox + dataframe filter). Meanwhile 7 sections at 30–60 min each is 3.5–7 hours of build scheduled into the only unbuffered window (Sun ~6–10 AM, after s5 produces a pattern).
FAILURE: 8:00 AM Sunday: Streamlit is behind, the cut order says 'switch to static HTML export'. You switch and discover the evidence-card click-through — the demo's best 15 seconds and on the design's own never-cut list ('evidence display') — doesn't exist in static Plotly. You either demo charts with no provenance moment or hand-build per-leaf HTML pages until the 10:00 freeze. Discovered at the exact moment there is zero slack.
FIX: Rewrite the fallback now: degrade by cutting Streamlit SECTIONS in reverse narrative order, never by switching stacks. Pre-rank sections: must-have = global stacked bar, moderator table (headline stat only), tree, evidence cards. Cheap adds = agent-loop trace as a static preformatted text block (15 min), residual contradictions as a plain table (30 min). Cut the heatmap NOW (it is already first-cut adjacent; the tree carries the same story). Single page, one selectbox, no other interactivity. Saves 2–3 hours Sunday morning and removes the stack-switch cliff.

[major] (§2 Architecture — content-addressed caching across 8 stages) Content-addressed idempotency (hash of question_id + stage params) across s0–s7 is infrastructure gold-plating for a one-weekend, one-question, one-operator pipeline. The failure modes of a hand-rolled cache key (prompt text not in the hash, unstable dict ordering, params that always change) are classic 2 AM sinks, and the machinery itself is 1–2 hours of build+test that produces zero demo pixels.
FAILURE: 11 PM Saturday: you fix the extraction prompt after G3 audit findings, re-run s3, and the cache key doesn't include prompt_version (or serializes params non-deterministically) — the stage silently serves the old extractions. You spend an hour concluding the 'improved' prompt does nothing, or the inverse: the key over-triggers and re-burns rate-limited map calls you needed for the overnight run.
FIX: Replace with: fixed output path per (qid, stage), a --force flag to re-run, and a sidecar run.json recording {timestamp, prompt_version, schema_version, result_ids, params} for provenance. That sidecar already satisfies context §45's minimum. Re-run decisions are made by the human, not a hash. Saves 1–2 hours of build plus the phantom-cache debugging tail.

[major] (§4.2 map extraction schema (≈25 fields per finding)) The per-finding schema carries fields that will be >80% missing or zero-variance in the shortlisted corpora and are never read by any planned analysis: route (oral everywhere in C/A), frequency (daily), assay, effect_size_type (numeric meta-analysis is already a stretch-goal cut). Every extra field in a strict additionalProperties:false schema raises the odds of output-validation failure, and Paperclip gives exactly ONE correction retry per map (verified) — so schema bloat directly taxes overnight extraction yield, plus each normalized field costs normalize.py code and tokens. The context doc itself warns: start core, inspect missingness, add iteratively — and the s6 remap stage exists precisely to add fields later.
FAILURE: Overnight s3 at scale: marginal papers fail validation on fields nobody will analyze, burn their single retry, and drop out. At 7 AM the corpus is 20% smaller than G3 projected, and normalize.py contains unit-parsing code for route/frequency/assay that no downstream stage ever reads.
FIX: Cut the v1 schema to ~15 fields: keep study_type, species/model, population_state, intervention, intervention_class (nullable), comparator, dose_raw, duration_raw, timing_context, outcome_name, outcome_family, timepoint_raw, effect_direction, sample_size, p_value/significant, evidence_quote, evidence_lines, confidence. Drop route, frequency, assay, effect_size, effect_size_type from pass 1; if a moderator needs one, that is what s6 remap is for. Saves ~1–2 hours of normalize/test code and protects overnight yield. Zero demo cost: the headline moderators (dose, timing, species, outcome_family) all survive.

[major] (D6 — 500 bootstrap + 200 permutations) Compute is not the real problem — ~100–300 findings, ~10 moderators, 5-fold grouped CV gives ~25k bootstrap fits + ~10k permutation fits of tiny logistic regressions: 10–20 min if written tightly, 60–90 min if each resample re-encodes via pandas/sklearn pipelines. The real problem is robustness: with a 3-class outcome, small strata, and paper-level resampling, some resample WILL produce a fold missing a class or a moderator level unseen at fit time, and sklearn throws. The design specifies the statistics but not crash handling or checkpointing for the unattended overnight run. Separately, the design never names which single stat carries the 90-second demo — five numbers per moderator (coverage, MI, ΔLL, permutation p, bootstrap top-3) is four too many for judges.
FAILURE: s5 launched at 1 AM dies at bootstrap resample ~140 on a single-class fold. Nobody is awake. At 7 AM there are no moderator stats at all, and Sunday's 4-hour window now includes debugging sklearn edge cases instead of assembling the dashboard.
FIX: Cut to 200 bootstrap / 100 permutations (rank-frequency and empirical p at these sizes are indistinguishable to any judge; saves nothing is lost scientifically at this n). Wrap every resample in try/except, log-and-skip degenerate ones, report the skip count, and checkpoint partial results to disk every 25 resamples. Dry-run the FULL battery on the 30-paper v1 dataset at M4 (~10:30 PM) before trusting it overnight. Pre-commit the headline now: grouped-CV ΔLL with permutation p is THE number; bootstrap top-3 frequency appears only if the overnight run completes; MI stays in the exported table and never in the demo UI. Saves 1–2 hours of 2 AM debugging and a muddled narrative.

[major] (D4 / s2 screen stage — LLM `filter` pass) Eligibility is decided twice: s2 runs a `filter --from` LLM pass, then the s3 map schema returns paper-level eligible/exclusion_reason anyway (D2). The deterministic parts of s2 (--article-type research-article, refine, DOI/PMID dedupe) are essential and nearly free; the LLM filter pass is a redundant full-corpus LLM sweep implemented, tested, and paid for out of an unknown rate-limit budget that the overnight extraction needs.
FAILURE: Saturday evening the filter pass runs over 150 candidates on the hackathon tier. At 1 AM the windowed maps start hitting RateLimitError; the extraction ceiling that s0 measured was silently spent on a screening decision the map schema would have made for free. Corpus lands under target and no one can say which call spent the quota.
FIX: Collapse s2 to deterministic-only: article-type filter + refine + dedupe (+ NCT regex for duplicate cohorts). Let the map's eligible/exclusion_reason field be the sole LLM eligibility judgment; reviews that slip through are marked eligible=false and excluded in s4. Keep `filter` in the back pocket only if triage shows extreme review pollution (topic A). Saves ~1 hour of implementation and one full-corpus LLM pass of rate-limit budget.

[major] (D10 / §5.2 — C+B merge 'at near-zero extra cost') 'Near-zero extra cost' is false where it matters: on the critical path to the 5 PM topic lock. A merged-corpus triage probe means extra search families, a fourth 10-paper probe extraction before rate limits are characterized, doubled synonym/anchor lists, and direction semantics that must hold for two mechanistically different intervention classes. And if the merge WINS, intervention_class will trivially dominate the moderator table — 'metformin differs from vitamin C' reads to judges as a confound, not a discovered hidden variable, weakening the core pitch.
FAILURE: 4:30 PM Saturday: the C+B merged probe is still extracting; G2 slips to 6 PM; G3 slips past 8; the overnight extraction window shrinks by the same amount. Alternatively the merge wins triage and Sunday's tree's first split is intervention_class, which any judge dismantles in one question.
FIX: Keep intervention_class as a nullable schema field (free). For triage, run count-only (-c) queries for B — two minutes — and NO merged probe extraction. Revisit the merge only if C's confirmed usable-primary count comes in under ~60 AND A also disappoints. Saves 1–1.5 hours on the tightest gate of the day.

[minor] (§4.1 FindingRow — research_group and author_conclusion_agrees) research_group is a post-hoc author-overlap computation ('later if time') that requires author-name disambiguation — a rabbit hole — for a lab-concentration sensitivity check that appears nowhere in the demo narrative. author_conclusion_agrees demands the extractor compare Results vs Conclusion per finding, inflating prompt complexity for a diagnostic that will be mostly null and is never displayed; the actual §41-2 mitigation (prompt prioritizes Results/Methods) works without the field.
FAILURE: Midnight: the coding agent, executing the plan literally, spends 45+ minutes on author-list clustering for a field with zero demo surface; or the audit at G3 flags author_conclusion_agrees mismatches and eats audit time adjudicating a field no one will show.
FIX: Cut both from the map schema and from v1 FindingRow. Keep the Results-first extraction prompt language. If a judge asks about lab concentration, answer verbally with the findings-per-paper table (already displayed). Saves 0.5–1.5 hours and slightly hardens schema validation.

[minor] (§8.3 validation plan — recovery check) The recovery check ('does the system recover moderator structure a published review already asserts') has no target if topic C wins: C's entire selling point per the research notes is that NO published meta-regression on the vit-C dose split is confirmed to exist. The validation plan silently assumes a recovery target that the preferred topic may not have.
FAILURE: Sunday 9 AM: validation section of the dashboard has a 'recovery' slot with nothing to put in it, or worse, the narrative claims recovery against a review that only asserted the dose story narratively — a judge who knows the literature calls it out live.
FIX: During triage, record per-topic what the concrete recovery target is (A: TRE early-vs-late from published MA — real target; C: none confirmed). If C wins, reframe the slot as narrative-consistency: 'the literature informally attributes the contradiction to dose; our tree finds the split quantitatively, which no published analysis has tested.' Costs zero hours; prevents a live credibility hit.
