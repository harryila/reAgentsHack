VERDICT: The design is unusually disciplined on statistical hygiene (grouped CV, permutation nulls, pre-registration) but the data-contract layer between LLM output and analysis has three silently-failing joints that the plan currently hand-waves: finding identity is defined against index fields that do not exist in the extraction schema and are unstable across LLM re-runs; the s6 remap merge-back — the mechanical core of the agentic-loop demo — has no join key or granularity contract; and the idempotency cache key does not provably include prompt/schema content, while G3 guarantees a mid-corpus prompt revision that would silently mix direction-label semantics. All three fail without raising errors, during the unattended overnight window, and all three have fixes measured in minutes if pinned before scaffolding starts (deterministic content-hash IDs scoped to a single map artifact; echo-back keyed remap or paper-level-only moderators; cfghash in raw filenames plus a single-version assertion in s4). Second tier: the topic-C headline depends on a dose parser nobody owns (push normalization into the extraction schema), DOI/PMID dedupe misses preprint↔published pairs (add title+author+year fuzzy pass), quarantine and evidence_quote-required semantics can silently shrink or bias the corpus, and the Streamlit artifact boundary needs a manifest with a pinned schema version to fail at rehearsal rather than live. Fix the three blockers in the scaffold (M0) and this pipeline is sound; skip them and the 2 AM failure mode is not a crash but wrong numbers on stage.

[blocker] (§4.1 FindingRow / §4.2 extraction schema — finding_id determinism) finding_id = "{paper_id}:{comparison_idx}:{outcome_idx}:{timepoint_idx}" is labeled deterministic, but the §4.2 map schema returns a FLAT findings array with no comparison/outcome/timepoint index fields and no nesting. The three indices must be invented post-hoc by grouping free-text LLM strings (intervention/comparator/dose_raw/outcome_name), and they are only stable within one raw map artifact — any LLM re-invocation (retry, prompt v2, s6) re-segments and re-orders the array, silently reassigning every ID.
FAILURE: G3 audit at 8 PM finds direction errors; prompt bumps to v2; s3 re-runs. Every finding_id shifts. The 15–20 row audit sheet keyed by finding_id now points at phantom rows — the demo's "N/20 audited rows correct" claim is computed against the wrong findings, or an inner join drops to 0 rows and someone hand-patches it at 2 AM. Worse: after s6, "P1:0:0:0" resolves to a physically different comparison than in the base run, so the remap moderator lands on the wrong row with zero errors raised.
FIX: Redefine finding_id = paper_id + map_result_id + array_position + 8-char content hash (outcome_name|timepoint_raw|dose_raw|effect_direction). Document explicitly: IDs are stable ONLY within one raw extraction artifact; never join across extraction runs by ID (see s6 finding). Key the audit sheet by (map_result_id, position) and pin the map_result_id it was audited against. Add array_position tiebreaker so two identical findings in one paper cannot collide.

[blocker] (§2 pipeline s6 remap / D7 / context §12 Pass 4 — merge-back join contract) s6 says "targeted moderator re-extraction, merge back" and the context says "Merge by paper/finding," but no remap output schema, no granularity decision (per-paper vs per-finding), and no join key are specified. A fresh LLM call will not reproduce the base run's comparison segmentation, so there is nothing to join on. This is the mechanical core of the agentic-loop demo segment, scheduled for overnight (M5) when no human is checking.
FAILURE: Agent proposes "antioxidant timing (pre- vs post-exercise)". If remap returns one value per paper, crossover papers with both pre- and post-dosing arms (common in this literature) get one timing value stamped on all their findings — the moderator is miscoded exactly where within-paper contrasts make it most informative. If remap returns an array of {comparison, timing}, it joins to base rows only by fuzzy string matching written at 3 AM. Either way the held-out ΔLL test evaluates a misaligned column: real signal destroyed (agent loop demos as "no gain, discarded" — the 'excellent' tier dies) or spurious gain (false headline in front of the Forking Paths coauthor).
FIX: Pin one of two contracts NOW: (a) paper-level remap only — constrain D7 proposals to paper-level constructs, merge on paper_id, accept the granularity loss explicitly; or (b) echo-back keying — remap prompt embeds the base run's finding list (finding_id + evidence_quote + outcome + dose_raw) and the schema requires output as {finding_id: <enum of the provided IDs>, value}, so merge is an exact key join; unmatched IDs go to quarantine, never guessed. Option (b) also works on the D1-F2 Claude-API fallback path unchanged.

[blocker] (§2 idempotency / D8 / context §45 — config hashing and version mixing) "Idempotent (content-addressed by question_id + stage params)" never states that prompt text, schema JSON, and the config's positive/negative direction definitions are part of the cache key. Rows carry prompt_version (D8), but no stage asserts version uniformity. G3 exists specifically to revise prompts after some extraction has happened — the version-mixing scenario is not an edge case, it is the plan.
FAILURE: G3 fix changes positive_definition/negative_definition wording at 8 PM. Overnight scale run extracts windows 4–12 with prompt v2; windows 1–3 sit on disk keyed by (qid, stage, offset) and are skipped as "cached." s4 concatenates all rows. A third of the corpus has direction labels under the OLD semantics — for direction definitions this can mean literally inverted labels. Entropy inflates, the dose moderator dilutes, every headline number is wrong, and no eyeball check catches it because each row is individually plausible. Audit sampled from v2 rows reports 90% precision while v1 rows are junk.
FIX: Cache key = sha256(prompt file + schema file + target_relation config block), truncated to 8 chars and embedded in raw filenames (map_<qid>_<cfghash>_w03.json) — changing any of them naturally misses cache. Add a hard assertion in s4: fail loudly if rows contain >1 distinct (prompt_version, schema_version, cfghash) tuple, overridable only by an explicit --allow-mixed flag. ~15 minutes to build now; unrecoverable at 9 AM Sunday.

[major] (§2 s4 normalize / §4.1 dose_raw / D10 topic C — dose parser unscoped) s4 is one line ("units, categories, raw preserved") but the pre-scanned headline result — vitamin C ~500 vs 1000 mg/day threshold — lives or dies on dose comparability. Real dose_raw values in this corpus: "1 g/day", "2 × 500 mg", "500 mg twice daily", "0.5 g·d⁻¹", "vitamin C (500 mg) + vitamin E (400 IU) daily" (most antioxidant-exercise trials co-administer C+E, so dose is a VECTOR of per-compound values, not a scalar), plus animal mg/kg/day that cannot share an axis with human mg/day. Nobody is assigned this parser, no time box exists, and IU→mg conversion is compound-specific.
FAILURE: 11 PM: moderator table shows dose coverage at ~45% because a one-hour regex handled only "NNN mg" patterns; the dose split fails the min-support threshold (3 papers / 8 findings per level); the headline dies with no time to iterate, or someone pools mg/kg mouse rows with mg/day human rows and the tree splits on an artifact of unit mixing.
FIX: Move normalization INTO extraction: add per-compound normalized fields to the schema (vitc_dose_mg_per_day: number|null, vite_dose_iu_per_day: number|null) and have the prompt do the g→mg and per-dose×frequency→per-day arithmetic, with dose_raw preserved for audit — the LLM reading in-context does this far better than a hackathon regex, and the audit sheet verifies it row-by-row. Keep s4 parsing as a spot-check only. Decide now: mg/kg animal rows get a separate stratum, never the same dose axis. If topic A wins triage instead, the same finding applies to eating-window parsing ("8-h TRE, 12pm–8pm").

[major] (D4 screening / risk register §41-8 — dedupe key gap: preprint↔published and cross-source duplicates) Dedupe is "by DOI/PMID" plus NCT regex. This misses: (a) a bioRxiv/medRxiv preprint and its published PMC version share neither DOI (10.1101/… vs journal DOI) nor PMID — and both source families are explicitly searched; topic A (TRE) is medRxiv-heavy; (b) the same article surfacing from both pmc and abstracts sources under different Paperclip doc_ids where one record has a null DOI passes DOI-dedupe trivially. NCT regex only helps registered clinical trials — most animal and exercise-physiology studies have no trial ID.
FAILURE: The same cohort enters as two paper_ids. Grouped CV and paper-level bootstrap — the design's proudest anti-pseudoreplication defenses — treat them as independent papers, silently defeating themselves; the duplicated study's direction gets double weight in exactly the statistics the demo cites for credibility. Noticed too late when a judge clicks a leaf's evidence cards and sees the same trial twice with identical n and effect sizes.
FIX: After the DOI/PMID pass, add a fuzzy pass: normalized title (casefold, strip punctuation) + first-author surname + year±1, via rapidfuzz (already in the optional stack; ~30 min). Prefer published over preprint on collision, record merges in a dedupe report (data/processed/<qid>/dedupe_log.jsonl) — the log itself is demo-credibility material.

[major] (§5.3 s3 boundary / §4.2 required fields — pydantic strictness vs LLM sloppiness, and quarantine accounting) Three unpinned contracts at the validation boundary. (1) No pre-pydantic coercion layer is specified: on the D1-F2 Claude-API fallback (a live possibility, since D2 is the plan's biggest unverified assumption) there is no server-side schema validation, and strict Literal enums will reject "Positive", "positive ", "no effect" — and the string "null" vs JSON null collision on effect_direction (required, non-nullable, whose valid value IS the string "null") means serializer confusion rejects precisely the null findings, biasing the corpus toward positive/negative and inflating entropy while looking like success. (2) Quarantine granularity is unstated — row-level or whole-paper? — and rejected rows appear in no defined denominator (coverage, the demo's "M findings", the audit sampling frame). (3) No rejection-rate alarm exists for the unattended overnight run. Separately, §4.2 makes evidence_quote required non-null while the research notes say omission is the dominant LLM error mode — the schema forces either fabricated quotes or silent row loss for genuine findings without a locatable quote.
FAILURE: Overnight scale run: 35% of rows quarantine on enum casing or a null evidence_quote. Sunday 7 AM the corpus is half the expected size, nobody has opened the quarantine file, and the narrative's "we read N papers, extracted M findings" no longer reconciles across stages — or worse, null-direction rows were disproportionately dropped and the disagreement statistics are quietly biased.
FIX: Specify a normalizer that runs BEFORE pydantic: strip/casefold enum values, alias map ("no effect"→"null", "increase"→"positive" per config), explicit string-"null"/None disambiguation for effect_direction, lenient p-value coercion. Quarantine at FINDING granularity with reason codes; s3 prints (and writes to manifest) accepted/quarantined counts and exits with a red banner if quarantine_rate > 10%. Make evidence_quote nullable: keep ungrounded rows in statistics, flag them, exclude from evidence cards, and report the ungrounded fraction honestly.

[major] (§2 s7 / D9 — Streamlit artifact contract and jsonl/parquet source-of-truth) s7's "frozen JSON/parquet consumed by Streamlit" pins no file list, no column schema, no version stamp, and no manifest; and the same logical dataset exists as findings.jsonl (s3) and findings.parquet (s4) with no declared source of truth. Also unstated: pandas jsonl→parquet dtype coercion turns nullable ints into floats (sample_size 24 renders as 24.0 on evidence cards) and bool|None into object columns.
FAILURE: Two concrete paths: (a) Saturday-night dashboard binds to column cv_gain; Sunday-morning s5 rerun (post-remap) renames it delta_ll — Streamlit KeyErrors live at 12:40 PM, or st.cache_data serves Saturday's stale frame because the file path never changed. (b) A 3 AM hand-fix applied directly to the parquet (mislabeled direction found in audit) is silently wiped when s4 re-runs from jsonl, and the demo shows the known-wrong row the team believes was fixed.
FIX: Declare findings.jsonl the single source of truth; parquet is always regenerated, never hand-edited; manual corrections go into a patches.yaml applied deterministically in s4 (with reason strings — audit material). s7 writes manifest.json {qid, schema_version, prompt_versions, cfghash, created_at, git_sha, row_counts, quarantine_counts, files+sha256}; streamlit_app.py asserts manifest.schema_version equals its own pinned constant at startup and renders created_at in the footer, so a stale or mismatched artifact fails loudly at Sunday-9AM rehearsal instead of live. Cast dtypes explicitly (Int64 nullable) in s4.
